# NumberInput — triage complete

Issue: https://github.com/juwel-development/LIB-design-system/issues/111

The maintainer approved the complete agent brief. It is
[posted on the issue](https://github.com/juwel-development/LIB-design-system/issues/111#issuecomment-5860696110),
which now carries `component-proposal` / `ready-for-agent`.

## Agreed with the maintainer

- Add a separate `NumberInput` roster entry, rather than extending Input's variants.
- Preserve entered text and emit strings so blank, zero, incomplete edits and
  locale-specific decimal text remain distinguishable.
- The consumer owns parsing, locale policy, validation and error wording. The
  maintainer accepted raw text as a trade-off, not as a claim that alternative APIs
  are impossible. A parsed result would still need the original text and a parsing
  policy; this proposal does not add that responsibility to the library.
- Reuse Input's uncontrolled value contract: `defaultValue` initializes the field,
  `reset$` clears it in place, and `onInput$` reports user edits. Restore saved text
  when remounting the field; no additional channel for arbitrary live value updates.

## Verification

- Source inspection at `2235675` (package 3.8.0) covered Input, TextArea, Slider,
  Select and public exports. None exposes freely typed numeric entry with a numeric
  keyboard hint. Input supports text/email/url and already emits strings.
- All 16 existing Input tests passed, including its reset command preserving focus
  on the same live input node.
- A jsdom value-assignment probe shows number inputs exposing an empty string for
  assigned `-`, `1.` and `1,5`, while text inputs with decimal input mode retain
  them. Both retain `0` and `1.5`. This verifies value sanitization, not real browser
  typing or mobile keyboard behavior.
- The HTML standard requires number-value sanitization and describes decimal input
  mode as a keyboard hint including the locale's decimal separator:
  https://html.spec.whatwg.org/multipage/input.html#number-state-(type=number)
  https://html.spec.whatwg.org/multipage/interaction.html#attr-inputmode
- Prior rejection #95 concerns parameterized content-rule props. ADR 0009 permits
  naming a field kind and leaves validation with the consumer; this proposal does
  not reopen min/max/step, patterns, input caps or clamping.
