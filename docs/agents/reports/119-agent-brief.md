## Agent Brief

**Category:** component-proposal (enhancement)
**Summary:** Add outlined and destructive Button variants and automatic label wrapping with constrained-width sizing.

This brief is the authoritative contract, superseding the original issue body where they differ.
The maintainer confirmed the complete contract during triage. Profile actions and other game-specific
concepts belong to consumers and introduce no library API.

**Current behavior and verification:**

Source inspection of Button, its tests and stories confirms three variants: primary, secondary and
ghost. Primary and secondary are filled and use the control minimum width; ghost is transparent,
padded and content-sized. Every variant currently prevents text wrapping. No outlined or destructive
variant exists. Shared focus styling, native disabled behavior, accessible naming and the existing
click output already exist. These are verified missing public contracts, not a reproduced runtime
defect; no browser reproduction or runtime tests were run during triage.

The redundancy search covered Button's implementation and examples, related interaction/layout
components, tokens, the domain glossary and #114's accepted brief. #114 owns the plain variant:
inherited typography, no button face, padding or minimum width, with natural wrapping. Reuse and
coordinate that work rather than introducing another inline or content-sizing API here. #119's new
variants need not wait for plain, but must preserve it if it has landed.

The prior-rejection knowledge base was checked. The control-boundary decision formerly excluded
outlined Buttons; the maintainer explicitly narrowed it to allow an opt-in outlined variant while
retaining the rejection of borders on filled Buttons. Focus-boundary reinforcement remains rejected:
the shared ring is the only focus change. ADR 0008 governs role-based props; ADR 0011 keeps status
tones general and requires their positional contrast constraints to accumulate.

**Desired behavior:**

- Add outlined: secondary-coloured text and border on an unfilled surface. Preserve the existing
  filled secondary variant and the distinct ghost treatment.
- Add destructive: one filled variant using the error role as fill with a dedicated contrasting
  text/ink role. Destructive is not an independent tone prop; there are no destructive combinations
  with outlined, ghost, plain, primary or secondary.
- Labels wrap automatically across every Button treatment when available width is insufficient.
  Short labels stay on one line when they fit. No wrapping prop, clipping or ellipsis is introduced.
- Outlined and destructive share primary/secondary padding and ordinary minimum-width behavior.
  All four can shrink below that minimum when the containing space is narrower. Height grows with
  wrapped content, preserving padding and usable hit areas. Ghost and plain retain their distinct
  content-sized contracts rather than inheriting the filled-button minimum width.
- Keep native button semantics, disabled behavior, accessible names and the shared focus ring.
  Consumers supply wording or meaningful symbols that communicate destructive meaning without colour.

**Key interfaces:**

- `Button.variant` adds `outlined` and `destructive`; primary remains the default. Preserve existing
  primary, secondary, ghost and any plain variant supplied by #114, except for the agreed wrapping
  and constrained-width changes.
- Preserve `onClick$`, `disabled`, `ariaLabel`, `type` and children composition. No consumer style,
  arbitrary DOM-prop, size or tone escape hatch is added.
- Extend the theme token contract with contrasting ink for the error fill. Follow existing token
  naming and generation conventions. Both themes and all shipped token entry points must agree.
  Hover treatment is an implementation detail using semantic roles and the existing colour-motion
  contract; it must preserve each variant's filled/unfilled identity and contrast.

**Acceptance criteria:**

- [ ] Outlined is visibly bounded with secondary-coloured text and border and an unfilled surface.
      Existing filled variants receive no visible border. Focus changes only the shared ring.
- [ ] Destructive is a standalone filled variant using error plus dedicated contrasting ink.
      No destructive tone prop or combinatorial destructive variants are introduced.
- [ ] Document and test positional token constraints in both themes: outlined text against surface,
      its identifying border against surface, destructive ink against its fill, and its identifying
      fill against surface. Preserve the existing library contrast floors (4.5:1 for normal text,
      3:1 for identifying boundaries/fills), including enabled hover states. Additional error uses
      must retain existing status-tone and Meter constraints.
- [ ] All variants display complete long translated labels through automatic wrapping. Verify text
      alone and text composed with an icon, narrow flex/grid containers, and a container narrower
      than the normal control minimum width. Button sizing must not force horizontal overflow where
      its content can wrap; long unbroken labels must remain readable. No fixed height clips lines.
- [ ] Outlined and destructive share primary/secondary ordinary sizing. All four shrink when
      constrained and preserve padding; ghost/plain retain their own contracts. Do not enlarge plain
      with padding or a minimum width to satisfy the standalone button sizing rule.
- [ ] Pointer and keyboard activation retain the existing click output; disabled buttons cannot
      activate and remain visibly distinguishable. Disabled outlined keeps its unfilled identity.
      Accessible text and icon-only names remain supported; default type remains button.
- [ ] Add behavior tests and Storybook examples for all variants, translated labels, constrained
      widths, disabled states and visible keyboard focus. Verify real wrapping, overflow, focus and
      hit areas in a browser; DOM/class assertions alone do not establish geometry. Exercise light,
      dark and forced-colors presentation. Follow repository implementation/testing standards.
- [ ] Update public documentation for variant selection, token constraints, automatic wrapping,
      shared sizing and consumer-owned destructive wording. Reconcile the prior boundary rejection
      with the accepted opt-in outline contract, retaining the prohibition on borders for fills.
- [ ] Run required lint, typecheck, tests, library build and Storybook build.
- [ ] Publish through the normal release process and record the actual released version in
      [the consumer ticket](https://github.com/juwel-dev/g-label-manager/issues/195). Report
      implementation and publication separately; triage does not constitute a release.

**Out of scope:**

- Game-specific actions, profile semantics, wording, availability, confirmation flows or domain logic.
- Additional content-sizing APIs or duplicate implementation of #114's plain treatment.
- Independent destructive tone, arbitrary size scales, optional wrapping, or borders on filled Buttons.
- Changes to the shared focus, motion or radius contracts beyond preserving their existing behavior.
