**Category:** component-proposal (enhancement)
**Summary:** Extend DefinitionList with per-list density and consistent, container-aware term/value proportions.

**Current behavior and verification:**

Source inspection confirms that DefinitionList has no density or allocation props. Each item uses a
fixed 16rem term track above a 64rem viewport breakpoint, regardless of its container's width.
Terms use subtitle typography, descriptions use body typography, and both have semantic family roles.
The component already provides semantic dl/div/dt/dd composition and multiple terms sharing a description.
Existing tests assert the viewport-based contract; stories cover default, single-item and multiple-term cases.
This is a verified missing public capability, not a browser-reproduced defect. Browser verification
of the new layout remains implementation work. The shared workspace had an unrelated merge in progress
during triage; no implementation or runtime checks were performed as part of this brief.

The redundancy search covered DefinitionList, its tests and stories, Table, ColumnLayout, the domain
glossary and relevant ADRs. ColumnLayout supplies the allocation precedent but is not a semantic
definition-list replacement. No direct prior rejection was found; Figure and Brandmark width rejections
caution against arbitrary size vocabularies. ADR 0008 records the explicit DefinitionList density
exception alongside the previously accepted Table exception.

**Desired behavior and key interfaces:**

- DefinitionList.Root gains `density?: 'comfortable' | 'compact'`, matching Table's accepted contract.
  Comfortable is the default and preserves current spacing. Compact reduces spacing through semantic
  theme tokens, without changing typography or descendant control dimensions. Density is per list.
- Consumers choose term/value proportions once for the whole list; every item shares that allocation.
  Follow ColumnLayout's positive relative weights and theme-token minimum-width vocabulary. Allocation
  describes the two semantic tracks, not individual items or current content lengths. Exact prop names
  and token identifiers are implementation choices within the existing closed prop contract.
- Use the list's available content width, after its column gap, to determine whether both proportional
  shares satisfy their minimum readable widths. If either does not, the entire list stacks each item's
  terms above its description. Like ColumnLayout, minimums decide the switch rather than forcing
  overflow in the stacked arrangement. Both densities use this container-based behavior.
- Provide documented semantic defaults when allocation is omitted, so existing composition remains
  usable without new mandatory props. Replacing the viewport breakpoint with container adaptation is
  intentional in both density modes. Preserve typography, hairlines, semantic markup and composition.
- Long phrases and unbroken text wrap within the allocated space. Preserve reading order and all
  content, including multiple terms sharing one description. Do not truncate, overlap, or introduce
  page-wide horizontal overflow. Resizing preserves descendant state, focus and keyboard order.
- Consumer content remains consumer-owned; Artist facts and game-specific rendering do not enter
  the library. Retain the closed prop surface, with no className/style escape hatch.

**Acceptance criteria:**

- [ ] Omitted density matches comfortable spacing; compact visibly reduces spacing. Both coexist on
      one page and respond to theme tokens, without changing typography or descendant control sizing.
- [ ] Consumer proportions apply consistently across all items despite short, long or changing text.
      Document defaults, valid weights, minimum-token requirements and invalid-configuration behavior
      consistently with ColumnLayout.
- [ ] A narrow list on a wide desktop stacks independently of a wide list beside it. Check widths
      immediately above and below the fit threshold in both densities, including changed theme minimums.
      Terms precede their descriptions and the entire list changes arrangement together.
- [ ] Long English/German phrases and unbroken values remain readable, with no overlap, clipping,
      ellipsis or page-wide horizontal overflow. Cover multiple terms, one item and an empty list.
- [ ] Preserve dl/dt/dd semantics, existing type roles, hairlines, composed links/controls and their
      focus/state through resizing. Density does not add interaction or modify content semantics.
- [ ] Add behavioral tests and Storybook examples for comfortable, compact, long-value and narrow-container
      cases. Use real browser geometry checks for proportions, wrapping and container adaptation; DOM
      class assertions alone do not establish those guarantees.
- [ ] Update consumer documentation and run required formatting, lint, typecheck, tests, library build,
      Storybook build and relevant browser checks. Coordinate with #120's typography contract.
- [ ] Publish through the normal release process and record the actual version in
      [Label Manager #195](https://github.com/juwel-dev/g-label-manager/issues/195). Report implementation
      and publication separately; triage itself publishes no release.
