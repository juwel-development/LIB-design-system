## Agent Brief

The maintainer confirmed this complete contract during triage. This brief is authoritative

**Category:** component-proposal (enhancement)
**Summary:** Separate heading, body and control font families through theme roles while preserving existing family contracts.

**Current behavior and verification:**

Source inspection confirms that headings, reading content, buttons and field values all use
the primary family. Changing that family to serif therefore changes all of them. Secondary
assignments distinguish labels, navigation, captions and annotations, rather than headings
from body text. The requested separation is a missing public contract, not a reproduced runtime
bug. No runtime or browser tests were run during triage.

The redundancy search covered typography primitives, PageHead, Dialog, DefinitionList, Table,
interaction components, token generation and shipped styles, tests, stories and consumer
documentation. No equivalent contract exists. The rejection knowledge base contains no matching
rejection. ADR 0004's two-family assignment must be amended; its rejection of per-instance font
props remains valid. Preserve ADR 0005's heading-level and size mapping.

**Desired behavior and key interfaces:**

- Introduce `--font-heading`, `--font-body` and `--font-control` as independently overridable
  theme family roles. Each defaults to the existing primary family, preserving consumer
  overrides of `--font-primary`. Retain `--font-secondary` and its current assignments.
- Heading family: H1–H6, PageHead's title and Dialog.Title.
- Body family: P, all Prose text, Checklist reading text, DefinitionList terms and descriptions,
  Table value cells, PageHead's lede and intro, and Dialog.Description. Audit any equivalent
  primary-family content added before implementation using the same semantic rule.
- Control family: Button treatments that own their typography, and the currently primary-family
  value/entry text in Input, NumberInput, TextArea, Select and MultiSelect. Placeholders follow
  their entry text. Do not reclassify secondary-family text inside controls: field labels,
  hints, errors, MultiSelect chips and other existing secondary assignments retain their family.
- Preserve deliberate inherited typography, including Link treatments and the plain Button
  contract owned by #114. A plain action inside a heading or paragraph follows that context.
  Coordinate with #119's Button variants without duplicating that issue's wrapping work.
- Family selection belongs to the theme; components assign roles without a font prop, raw font
  values, style/className escape hatches or new heading-size selectors. Consumers supply fonts.

**Acceptance criteria:**

- [ ] Changing heading family changes every listed heading without changing body, control or
      secondary text. DefinitionList terms remain body-family content regardless of their size.
- [ ] Body and control families can each change independently. Secondary-family and intentionally
      inherited text retain their documented behavior.
- [ ] Themes setting only primary and secondary families retain their previous computed font
      families. Verify this with actual differing families, not only the shipped inherit defaults.
      Verify overrides in supported theme scopes and all generated/shipped token entry points.
- [ ] Preserve size, leading, tracking, weight, document semantics, accessible names, interaction
      and focus contracts. Family changes retain complete readable text and existing wrapping
      behavior; they must not introduce clipping. Font metric changes may alter line breaks.
- [ ] Add meaningful contract tests and a representative Storybook composition demonstrating
      serif headings with sans-serif body and controls, plus a distinct control-family example
      proving independence. Include secondary text, nested links/plain actions and legacy themes.
- [ ] Verify computed families, multiline text, long translated labels and visible keyboard focus
      in a browser. Class-name assertions alone do not prove family resolution or layout behavior.
- [ ] Document role coverage, defaults, overrides and compatibility in consumer-facing docs.
      Reconcile the typography ADR and glossary. Font-feature requirements follow the effective
      family where features are used, including tabular figures; do not leave them stated only
      against a legacy token whose override can now be bypassed.
- [ ] Run the repository's required lint, typecheck, tests, library build and Storybook build.
- [ ] Publish through the normal release process and record the actual released version in
      [the consumer ticket](https://github.com/juwel-dev/g-label-manager/issues/195).
      Report implementation and release status separately; triage itself publishes no release.

**Out of scope:**

- Choosing or bundling Label Manager's fonts, copying its theme, or modifying the game's UI.
- Reassigning secondary-family text, redesigning type sizes/leading, or adding per-instance font selection.
- Reimplementing Button wrapping/variants, Tabs readability, or other separately tracked work.
- Guaranteeing identical geometry for arbitrary consumer fonts.
