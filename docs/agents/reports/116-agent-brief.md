## Agent Brief

**Category:** component-proposal (enhancement)
**Summary:** Add ColumnLayout, a compound Arrangement of weighted columns that becomes one column when its available width cannot satisfy every track's token-defined minimum.

**Current behavior and verification:**
Source inspection of Stack's public interface, recipe, tests and stories confirms that its split direction changes from column to row at a 64rem viewport breakpoint, without proportional child allocations or per-track minimums. Redundancy checks covered Stack, Cluster, DefinitionList, public layout components and source searches for proportional, grid, flex-basis and container-query behavior. No equivalent general Arrangement exists. This is verification of a missing public contract from source inspection; browser geometry remains implementation validation, not a reproduced defect claimed by triage.

The consumer need is supported by [Label Manager #195](https://github.com/juwel-dev/g-label-manager/issues/195): a roughly 2:1 table/summary arrangement that stacks when space is insufficient. The prior-rejection knowledge base has no matching rejection. Figure-width and Brandmark-size rejections concern other ownership boundaries. ADR 0008 records this arrangement's explicit authorization for structural weights and consumer-defined minimum-width token references.

**Accepted behavior:**
- Introduce a separate ColumnLayout Arrangement. Do not extend, replace or remove Stack or its existing split behavior.
- Support any number of rendered columns through the compound API. Each column declares its relative weight and minimum-width token reference; content belongs to the consumer.
- In the horizontal arrangement, subtract the gaps from the root's available content width and divide the remaining width in proportion to positive weights. A 2:1:1 allocation gives the first column half and each other column a quarter of that remainder.
- Stay horizontal only when every proportional share satisfies its own minimum. If any share is smaller, stack ALL columns into one column. Do not progressively wrap, clamp individual shares, or redistribute away from the requested proportions to postpone stacking.
- Evaluate the space available to this component, not the viewport. At the exact minimum-satisfying boundary the horizontal arrangement fits. For n columns, total weight S, gap g and resolved minimums m_i, the horizontal fit threshold is `(n - 1) * g + max(m_i * S / weight_i)`.
- In stacked mode, each column fills the available width even if narrower than its minimum. Minimums are switching criteria, not persistent width floors. Content owns wrapping or residual scrolling; the arrangement adds no scrolling, truncation or content-specific behavior.
- Columns align at the top and retain their own height. The same selected semantic gap separates columns in both horizontal and stacked arrangements.
- Rendered columns alone participate. Omitted conditional children reserve neither width nor gaps. A single column fills the available width; an empty arrangement contains no tracks or gaps. Update allocations when columns, weights, gaps, available width or resolved theme minimums change.
- Preserve DOM reading order, keyboard order and the mounted identity of retained children when the arrangement changes. Resizing must not reset child state or lose focus. No focus controls, landmarks or product semantics are added by the arrangement itself.

**Key interfaces:**

```tsx
<ColumnLayout.Root gap="region">
  <ColumnLayout.Column weight={2} minWidth="--main-column-min-width">
    …
  </ColumnLayout.Column>
  <ColumnLayout.Column weight={1} minWidth="--support-column-min-width">
    …
  </ColumnLayout.Column>
</ColumnLayout.Root>
```

- `ColumnLayout.Root`: compound root with children and optional `gap: 'stack' | 'region'`, defaulting to `region`. Read the existing space tokens. Preserve the repository's closed prop and public export conventions.
- `ColumnLayout.Column`: compound member with children, required positive finite numeric `weight`, and required `minWidth` referencing a consumer-defined CSS custom property by name, for example `--main-column-min-width`. Accept token names, not raw lengths, arbitrary CSS expressions, `var(...)` strings, className or style overrides. Constrain the token-name shape in public types.
- The consumer declares each referenced token in the applicable theme with a valid nonnegative length. Do not introduce library presets such as comparison/summary or a small/medium/large width ladder. Document token scoping, supported length resolution and the caller's obligation to supply valid tokens; missing/invalid tokens are not a valid responsive configuration.
- Follow repository conventions for compound composition and programmer errors. Document valid composition and reject invalid weights or malformed token names consistently with those conventions. The implementation mechanism is open, but must honor container resizing and theme changes without unstable switching or stale allocations.

**Acceptance criteria:**

- [ ] Browser geometry demonstrates 2:1 and 2:1:1 proportions after gaps, top alignment and unchanged reading order. Include more than two columns, unequal content heights and fractional positive weights.
- [ ] At widths immediately below, equal to and above the calculated fit threshold, verify the agreed all-or-one arrangement. Demonstrate a narrow container on a wide viewport and two independently sized instances.
- [ ] A column whose proportional share fails its minimum triggers stacking even when the sum of minimum widths plus gaps would fit. In stacked mode every column fits its holder despite its larger minimum.
- [ ] Verify zero, one and multiple rendered columns, conditional omission and subsequent insertion, updated weights and both gap roles. Remaining columns redistribute; no empty reserved slots remain.
- [ ] Consumer theme token changes affect the threshold. Document and demonstrate token-defined minimums in real CSS length units, including font-relative theme values, without accepting literal-width props.
- [ ] Test long text, translated labels and representative table/summary composition. Content remains accessible through its own wrapping/scroll contract; ColumnLayout must not itself force page-wide overflow or overlap tracks.
- [ ] Keyboard traversal follows child order in both modes; focus and child state survive container resizing. No remount is required merely to change arrangement.
