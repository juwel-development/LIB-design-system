## Agent Brief

The maintainer accepted narrowing this issue to the verified label-wrapping gap,

**Category:** component-proposal (fix to an existing component)
**Summary:** Keep long Sidebar labels fully readable within the existing responsive arrangement.

**Current behavior and verification:**

Sidebar already provides the requested responsive arrangement and non-color active
treatment. At and above 64rem it places a fixed 12rem navigation track beside the
content; below that viewport width the complete navigation list sits above content
in normal flow. The active entry has a persistent underline and `aria-current="true"`.
The consumer owns active state, section changes, routes and history.

Triage passed all 13 existing Sidebar unit tests. Headless Chrome checks at viewport
widths 1440, 1280, 1024, 1023 and 800 CSS pixels, with height 900, confirmed the
side/stacked transition, no page-wide horizontal overflow in the controlled example,
Tab skipping inert entries, Enter/Space activation, the active underline and a solid
3px focus outline with 2px offset. This verifies the library examples, not the
assembled game. Sidebar source matched the published v3.9.1 tag exactly.

The confirmed gap is long unbroken translated text. In the existing LongLabels
Storybook example at 1440px, replacing an entry's text with
`Vertragsverhandlungsübersicht` produced 243px of text inside a 173px-wide button.
The navigation measured 183px wide with 248px scroll width and computed horizontal
overflow `auto`; the label was visibly cut off until horizontally scrolled. Long
English phrases wrapped at spaces, and injected German phrases fit at 800px when
the navigation was above content. These German strings were test inputs injected
into the rendered story, not existing game translations.

The redundancy search covered Sidebar's implementation, public contract, unit tests
and stories, responsive/scrolling arrangements, the domain glossary and relevant
ADRs. Responsive placement and active treatment are already implemented. Existing
coverage does not prove long-word wrapping; the Stacked story declares a mobile
viewport preset rather than a narrow-desktop example. No prior-rejection entry
blocks this work. The shared focus-ring and closed component contracts still apply.

**Desired behavior and key interfaces:**

- `Sidebar.Item` / `ISidebarItemProps.children` remains a string section label.
  Wrap normal phrases naturally and allow words longer than available space to
  break sufficiently to remain fully readable inside their button and navigation
  track. Do not require horizontal navigation scrolling, truncate text, substitute
  ellipses or make a tooltip the only way to read a label.
- `Sidebar.Root` preserves its existing viewport-based side/above-content
  arrangement, navigation landmark, entry order and vertical scrolling behavior.
  Labels must not widen the side track or displace content.
- Preserve `active`, `entryKey`, `onSelect$` and `inert` behavior. The active entry
  retains its non-color underline and accessible current state; native buttons,
  keyboard order, activation and visible focus remain intact in both arrangements.
- Document and demonstrate the existing responsive contract and the strengthened
  label-readability guarantee using broad and narrow desktop examples.

**Acceptance criteria:**

- [ ] The existing side arrangement and above-content arrangement remain supported,

- [ ] Navigation naming, native non-submitting button semantics, active current

- [ ] Oversized navigation still permits vertical access to every entry, including
