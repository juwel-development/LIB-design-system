## Agent Brief

The maintainer confirmed this contract during triage. This brief is authoritative and supersedes
the original issue body wherever they differ.

**Category:** component-proposal (enhancement)
**Summary:** Extend Header with an explicit status/action mode while preserving its existing navigation mode.

**Current behavior and verification:**

Header always renders its children inside a nav and has no status/action slots. A server render
with Date/Balance in the standing slot and a Continue button as children confirmed the button
is wrapped in nav. All 13 existing Header tests passed during triage. Browser layout verification
has not been performed.

The redundancy search covered Header, Cluster, PageHead, FieldRow, their relevant contracts,
the domain glossary and ADRs. Cluster provides wrapping and opposite-edge distribution, but
does not provide the full shell contract or right alignment of a lone or wrapped action.
No matching prior rejection was found. The related Brandmark decision protects the existing
standing-slot sizing contract.

**Desired behavior and key interfaces:**

- Extend Header with an explicit status/action mode; preserve existing navigation behavior.
- The modes are separate: status/action mode does not also accept the standing link or navigation.
  Existing callers retain navigation mode without migration. Document the mutually exclusive
  prop shapes and enforce them through the public TypeScript contract. Exact mode/prop names are
  implementation choices; status and actions are separately documented content slots.
- Status/action mode supplies the shell header and its existing edge treatment, using semantic
  layout tokens. Its slot wrappers are neutral containers, not navigation landmarks. Status-only,
  action-only and both-slot compositions are supported; omitted slots reserve no space.
- Status precedes actions in reading order. When both cannot fit side by side, actions move
  below status and remain right-aligned. Actions also remain right-aligned when status is absent.
- Long labels wrap. Date, Balance, action availability and application behavior remain consumer-owned.
- Header adds no automatic live region or status announcement. It preserves consumer-supplied
  semantics; the consumer decides which updates to announce and supplies any live-region behavior.
- Preserve supplied headings, accessible names, button behavior and keyboard order. Changing
  available width must not remount content, discard descendant state or lose focus. Keep the
  existing navigation mode's standing-slot floors, type role and current-page treatment.

**Acceptance criteria:**

- [ ] Existing Header callers render the existing standing/navigation arrangement unchanged.
- [ ] The public contract exposes separate modes and rejects mixed standing/navigation and
      status/action props. Document slots, defaults, landmark placement and consumer responsibilities.
- [ ] Status/action mode renders no library-created nav, status role or live region. Supplied
      heading, status/live-region and control semantics survive unchanged.
- [ ] With both slots fitting, status occupies the left edge and actions the right content edge.
      Below the fit threshold, actions move below status and remain right-aligned. Status-only
      content stays left; action-only content stays right without an empty reserved status slot.
- [ ] Long labels, including English/German wording and unbroken text, wrap without clipping,
      overlap, ellipsis or page-wide horizontal scrolling. Gaps and insets use semantic tokens.
- [ ] Controls retain keyboard operation, visible focus, reading order and state across resizing.
      Header does not change action availability or add game behavior.
- [ ] Add behavioral tests using the repository's test-first workflow and Storybook examples for
      status-only, action-only, both-slot, long-label and narrow-desktop cases. Check rendered
      geometry and focus in Storybook at widths above and below wrapping; jsdom/class assertions
      alone do not prove layout. Include existing navigation mode in regression verification.
- [ ] Run lint, typecheck, tests, library build and Storybook build; record browser verification.
- [ ] Publish through the normal release process and record the actual version in
      [Label Manager #195](https://github.com/juwel-dev/g-label-manager/issues/195). Report
      implementation and publication separately; triage itself publishes no release.

**Out of scope:**

- Combined standing/navigation/status/action layouts, new game navigation, sticky/mobile-menu
  behavior, automatic announcements, date/Balance formatting or Continue/Run rules.
- Arbitrary CSS measurements, className/style escape hatches or changes to other components.
