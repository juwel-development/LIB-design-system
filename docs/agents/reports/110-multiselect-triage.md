## Agreed with the maintainer

- Add a dedicated `MultiSelect` component.
- Give it the appearance of an ordinary dropdown/select control, with a visible label
  and dropdown arrow. Its open surface is anchored beneath the control and contains
  a single column of checkable options.
- Each toggle takes effect immediately. The dropdown stays open while selecting;
  closing preserves the selection. There is no Apply/Cancel step.
- Selected options appear as individually removable chips.
- The control must stay on one line. Show chips that fit and a `+N` indicator for
  remaining selections. Opening the dropdown exposes all options.
- Offer a clear-all action when the selection is nonempty, including clearing
  selections hidden behind the overflow indicator.
- The consumer owns options, stable identities, selection, wording and the meaning
  of the selected set. Zero, one, several and all options can be selected.
- Selection uses separate streams: `selected$` is a read-only Observable input and
  `onChange$` is a Subject output carrying the full proposed selection after a user
  toggle, chip removal or clear-all. The app feeds accepted changes back into the
  selection input. External restore/clear and rendering emit no user-change event.
  The component owns subscription teardown; the consumer owns stream lifetime.
- When an option disappears, the app reconciles the selected identities with the
  options in the same logical update. The component does not silently prune or
  invent consumer-owned selection.
