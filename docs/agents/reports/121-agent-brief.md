## Agent Brief

The maintainer confirmed this complete contract during triage. This brief is authoritative
and supersedes the original issue body where they differ.

**Category:** component-proposal (enhancement)
**Summary:** Support rich, wrapping tab labels and document token-based separation between the tab list and panels.

**Current behavior and verification:**

Tabs accepts string-only tab children and explicitly promises a single scrolling row with
no wrapping or shrinking. Panels have no built-in separation from the list. Selection,
tab/panel associations, arrow navigation and panel mounting already have coverage: all
24 existing Tabs tests passed during triage. These tests use jsdom and do not prove visual
layout, wrapping or focus-ring visibility. Browser verification remains implementation work.

The redundancy search covered Tabs contracts, tests and stories, Stack, spacing tokens,
the domain glossary and relevant ADRs. Stack already supplies the spacing roles required
for panel separation; the rich-label and wrapping contracts are missing. No prior rejection
applies. The disabled-tabs knowledge-base entry is a separate deferral and stays in force.
The consumer specification requests wrapping translations and clear Stack spacing.

**Desired behavior and key interfaces:**

- Widen `ITabsTabProps.children` from `string` to `ReactNode`. Continue accepting existing
  string labels. Support visible text with optional icons, badges/counts and inline formatting.
  The consumer supplies a meaningful visible text name and valid non-interactive content;
  nested links, buttons, inputs and other interactive/focusable descendants are outside the
  contract. Decorative content must not pollute the accessible name; meaningful content
  remains available to assistive technology. Tabs remains the single interactive control.
- Keep tab controls in one horizontal row. Allow label text to wrap within a tab as available
  space narrows; retain horizontal scrolling when the row still cannot fit. Do not wrap the
  controls into multiple rows. Do not truncate labels, replace them with ellipses, or require
  a tooltip to read the full name. Handle long unbroken text without inaccessible clipping.
  A rich label must not defeat the component's supported text-wrapping behavior.
- Preserve existing selection and focus contracts: consumer-owned `active` and `onSelect$`,
  stable value-based associations, automatic activation requests on Left/Right navigation,
  wrap-around navigation, roving tabindex, active-panel focusability and inactive-content
  unmounting. Preserve focus visibility and access to focused tabs in an overflowing row.
- Document `Stack` inside `Tabs.Root`, containing `Tabs.List` and the matching `Tabs.Panel`
  siblings. `gap="stack"` or `gap="region"` selects an existing spacing role. Panels remain
  associated through Tabs context; hidden panels must not introduce extra visible gaps.
  Keep individual tabs as direct DOM children of the list. Clarify the existing composition
  wording so this wrapper is explicitly supported.
- Keep spacing consumer-selected through composition. Add no Tabs-specific gap prop, new
  spacing token or style/className escape hatch. Update the old string-only and no-wrap
  guarantees in published component documentation and examples.

**Acceptance criteria:**

- [ ] Existing string-label consumers remain supported. A rich label containing visible text,
      an icon and a count renders and selects as one tab; its accessible name is meaningful.
      Clicking non-interactive label descendants requests the same stable tab value.
- [ ] Short labels and long English/German labels remain fully readable at broad and narrow
      desktop widths. Label text wraps within controls while the controls remain one row.
      Long unbroken text remains reachable without page-wide horizontal overflow.
- [ ] In actual overflowing layouts, every tab remains reachable by pointer and keyboard;
      focused content and its focus indicator remain usable and visible. No label text is
      silently clipped, truncated or available only through a tooltip.
- [ ] Preserve tablist/tab/tabpanel roles, associations, selection, navigation, focus behavior
      and panel lifecycle for both text-only and rich labels, including composed Stack spacing.
- [ ] Stack composition separates the list from the active panel using the selected library
      space role. Switching between first, middle and last panels leaves the intended gap
      unchanged; inactive panels create no additional gaps.
- [ ] Add meaningful behavioral tests and Storybook examples for short labels, rich labels,
      long translated labels, narrow widths, keyboard navigation and both spacing roles.
      Browser checks verify wrapping, overflow, actual separation and visible focus;
      DOM tests or class-name assertions alone are insufficient for layout claims.
- [ ] Consumer-facing documentation explains rich-label restrictions, accessible naming,
      wrapping/scrolling behavior and the supported Stack composition.
- [ ] Run required lint, typecheck, tests, library build and Storybook build.
- [ ] Publish through the normal release process and record the actual released version in
      [the consumer ticket](https://github.com/juwel-dev/g-label-manager/issues/195).
      Report implementation and release status separately; triage itself publishes no release.

**Out of scope:**

- Disabled tabs, icon-only tabs, nested interactive controls, closable/reorderable tabs,
  multiline rows of tab controls, routing or a new selection model.
- Game-specific labels, consumer screen changes, panel caching or state preservation.
- New typography roles, arbitrary styling props or a second spacing mechanism.
